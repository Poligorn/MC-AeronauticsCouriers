# Aeronautics Couriers — уточнения к ГДД v3 (25.10.2026)

Источник истины — [`GDD.md`](GDD.md). Здесь собраны решения и замечания, принятые после его написания.

## Решения владельца (25.10.2026)
Ответы Egor на вопросы из `STATUS.md`. Нормативно; внесены в GDD v3.1.
1. **Лицензия мода — MIT** (`LICENSE`, `mod_license=MIT`). Из Create: Marketplace берём только идею UI и логику открытия окна (настраиваемое место кнопки). Их код не используем и не копируем.
2. **Сроки — игровые тики сервера.** Пока сервер выключен, таймер не идёт (GDD §5.4).
3. **Стартовый XP при миграции** 0 / 300 / 1500 / 5000 — оставить для теста.
4. **При провале** награда возвращается заказчику вместе с залогом курьера. Курьер рискует, но прозрачно: до принятия он видит, что именно потеряет (манифест, сообщение при принятии) (GDD §5.2, §7.2).
5. **Почтовая станция** `aerocouriers:post_station` — только для NPC-заказов, вместо колоколов (GDD §6).
   - Генерируется вместе с деревнями через worldgen, без ломания ванильных пулов и пулов других модов.
   - Есть UI с названием пункта: имя генерируется из словаря, оператор может его менять.
   - Администраторы ставят станции сами, чтобы создать свои пункты.
   - Атлас регистрирует станции, когда игрок с лицензией подходит ближе N блоков. Это и есть `ContractSource` для NPC-заказов.
6. **Контур зон частицами** — видит только курьер этого заказа, рисует клиент. Конфиг: плотность частиц и дальность (GDD §10.3).
7. **Крепление для верёвки** — `simulated:rope_connector` на контейнере, своей проушины нет. Проверено по исходникам Simulated 1.3.0 (GDD §9.4.1).
8. **Повреждение груза (пиратство)** — контейнер можно сломать или взорвать.
   - Заказ проваливается с причиной `DAMAGED`; залог и награда — заказчику.
   - Часть манифеста выпадает в мир один раз и атомарно.
   - Учитываются приваты и `[piracy]`; прочность и доля выпадения настраиваются.
   - Хрупкий груз (бэклог) пойдёт тем же путём (GDD §9.7).

- **30.10.2026, моргание на части скинов.** Пластина сидела в плоскости оверлея рукава (`y = -2.25/16` = верх `CubeDeformation.extend(0.25)`). На скинах с непрозрачным вторым слоем (jacket/sleeve) это z-fighting. Пластина сдвинута на 0.25 px выше оверлея (`y = -2.50/16`); glow по-прежнему +0.001; формат текстур не менялся. Скрытую часть руки (`ModelPart.visible` / `skipDraw`) не рисуем. Ширина slim/wide (3/4 px) не менялась.

## Особенности сборки MC-Ikaria (важно для дизайна)
1. **Мир — небесные острова, обычных деревень почти нет.** Решено (п. 5 выше): NPC-заказы идут только от почтовых станций. В обычных мирах станции генерируются в деревнях, на Ikaria их ставит администратор. Абстракция `ContractSource` остаётся.
2. **FFItemWeight** уже в сборке со своими весами предметов. Если мод установлен — брать вес груза из него (soft-dep), иначе свой `item_weights.json`.
3. **Дыра:** при провале деревенского/NPC-заказа груз НЕ отдаётся курьеру (иначе это покупка груза по оценке, выгодно при заниженной оценке редкого груза). Груз NPC-заказа при провале уничтожается.
4. В сборке есть мод Envelope со своими «курьерами» — избегать путаницы терминов в UI.
5. Waystones телепортируют только в пределах измерения. Межмировые заказы в коде есть с ранга IV (`AcceptEligibility`); отдельный UI карточек — 0.3.0. Waystones на межмир не влияют.
6. ⚠️ Уточнить у Simulated Project, можно ли использовать слово «Aeronautics» в названии аддона.

## Создание заказа штампом, доска только для мониторинга, одна станция на деревню (25.10.2026)
Решения владельца после теста доставки в игре. Нормативно; внесены в GDD.
1. **Транспортная накладная** `aerocouriers:transport_waybill` — единственный способ игроку создать P2P-заказ (крафт: 2× бумага + чернильный мешок + `minecraft:iron_nugget` + любой деревянный полублок `minecraft:wooden_slabs` → 2 накладные). ПКМ по контейнеру с инвентарём открывает окно оформления; одна накладная списывается только после успешной публикации на сервере. После подтверждения сундук на месте становится физическим грузовым контейнером (Sable), груз уходит в Escrow, исходный блок снимается без дропа. Устаревший `courier_stamp` остаётся зарегистрированным и мигрирует в накладные при тике инвентаря или использовании.
2. **Команда** `/couriers contract create` остаётся для операторов и тестов (ленивое появление контейнера при подлёте, как раньше).
3. **Отмена / истечение штампового заказа:** груз возвращается **в почту заказчика**, физический контейнер снимается без дропа. Не восстанавливаем исходный сундук: тип контейнера (бочка, двойной, модовый) уже потерян, чанк может быть выгружен, на месте может стоять что-то другое. Почта уже есть в шапке доски.
4. **Стыковка с ленивым появлением:** у заказа флаг `preplaced`. Пока `OPEN`, контейнер уже стоит и не удаляется самопроверкой. При принятии заказ сразу `IN_TRANSIT` (контейнер уже есть; иначе слот ранга зависает, если курьер улетает до следующего тика). Командные заказы по-прежнему появляются при подлёте.
5. **Доска (J, кнопка инвентаря, `/couriers ui`, ПКМ по станции, ПКМ по планшету)** — только мониторинг: вкладки «Заказы» и «Мои», почта и баланс в шапке. Вкладки «Создать» нет. Вкладка «Тест» у оператора: кнопка «Выдать накладные». Нужен **планшет заказов** в слоте Curios `order_tablet` или в руке; иначе подсказка «Нужен планшет заказов». Накладная по контейнеру планшет не требует. `[access] require_tablet = false` снимает проверку на сервере.
6. **Одна почтовая станция на деревню.** Причина дублей: элемент станции добавлен в пул домов; кусок 3×3×3 почти всегда влезает, поэтому jigsaw берёт его как запасной вариант, когда крупные дома не проходят (типично 5–7 кусков на деревню). Дедуп только в `onLoad` BE не успевал заменить копии — в мире оставались блоки `post_station` без `station_id`. **30.10.2026:** при постановке куска `OncePerVillageStationProcessor` оставляет первый `post_station` (клейм по старту деревни или по позиции) и сразу меняет остальные на стол картографа. BE-дедуп (тот же старт / радиус 96 / BE с `station_id`) — страховка для старых чанков. Станции оператора (`village=false`) не заменяются.

## NPC-заказы между станциями (итерация 5, 25.10.2026)
- Источник — **любые** станции в атласе: и деревенские, и поставленные администратором. На Ikaria деревень почти нет, поэтому админских станций достаточно. Пара в одном измерении, ≤ 10 000 блоков.
- Груз появляется физическим контейнером у станции погрузки сразу при публикации (`preplaced`). Награда минтится, со станции не списывается.
- При провале и истечении: залог сгорает, награда не выплачивается, груз уничтожается (не почта, не дроп).
- Стажировка: первые 3 принятых деревенских заказа без залога; после 3-й доставки — разовый аванс 100 сп.
- На доске NPC-заказ виден, если игрок открыл обе станции.
- Не в этой итерации: репутация станции, редкий груз, отдельное окно станции, лимит 800 блоков и подсказки стажёра.

## Отладка одиночной игры (25.10.2026)
- Серверный ключ `[debug] allow_self_accept = false` (только для тестов): если `true`, заказчик может принять свой P2P-заказ командой `/couriers contract accept` и кнопкой «Принять» на доске. В чат пишется предупреждение об отладочном режиме.
- Деньги и предметы идут на один UUID: игрок должен иметь на счёте награду + комиссию + залог. При доставке залог и награда возвращаются ему же (нетто − комиссия); при провале — то же. Почта, XP и `M_повтор` считаются как обычно (пара курьер+заказчик совпадает). Отдельной ветки выплат нет.
- **30.10.2026.** Пока контейнер переносит Sable, `containerRemoved` не валит заказ сразу: 60 тиков без нового отчёта `CargoTracker`, потом `DESTROYED` (OPEN штамп — истечение и почта). Снятие доставки удаляет блок только если на точке всё ещё BE этого заказа. Опечатанный ящик (`locked=true`) в physics JSON стоит последним и держит массу 0, иначе заполнение перебивает печать. Принятый штамп, который не собрался, `tick` снова зовёт `unlockAndAssemble`. Если при `DAMAGED` курьер и заказчик — один UUID, весь манифест целиком уходит в почту, в мир не дропается. Уведомление заказчику и курьеру не шлётся дважды на один UUID.
- **30.10.2026, самопринятие штампа.** Зона A накладной берёт тот же радиус, что и B (по умолчанию 8). Близкая точка B тогда содержит A; курьер при самопринятии стоит на ящике → три still-check'а «доставляли» его на месте, контейнер пропадал, тост категории ORDERS в чат не шёл. Если контейнер в пересечении зон, `checkContainer` считает доставку только когда он ближе к B, чем к A (A≡B — исключение). Нельзя просто запретить зону A целиком: NPC-станции имеют радиус 12, и близкая пара A/B иначе никогда не сдаётся. Если Sable при unlock съел тело — лог + срочное сообщение, респаун у A (Escrow не трогаем). Пакет `accept` с доски всегда пишет action bar; исключение в unlock не глотается. Экономика без отдельной ветки: создание −(награда+комиссия), принятие −залог, доставка +(награда+залог), нетто −комиссия.
- Свой открытый заказ **не** занимает слот активных перевозок ранга. Лимит `maxActive` (rank1 = 1) считает только `ACCEPTED`/`IN_TRANSIT`, где этот игрок — курьер. `max_open_per_player` ограничивает только создание. Штамповый заказ при принятии сразу переходит в `IN_TRANSIT`. Отказ по лимиту называет id уже везущегося заказа.

## Валюта без Numismatics — изумруды (29.10.2026, 0.1.14-alpha)
- Пока активен бэкенд Numismatics (`economy.backend` = `auto` или `numismatics` и мод загружен), суммы и баланс **те же шпоры**, что раньше. Делитель = 1.
- Иначе валюта — `minecraft:emerald` в инвентаре игрока (включая оффхенд). Изумрудный блок считается как **9** изумрудов: при списании сначала уходят россыпью, потом блоки разбиваются, сдача возвращается изумрудами. Если сдача или начисление не влезает — почта с кнопкой «Забрать». Оффлайн-игрока инвентарь не просканировать: баланс для него 0, начисление сразу в почту. Старый внутренний гроссбух при входе переводится в изумруды и обнуляется.
- Пересчёт один: `MoneyScale.fromSpurs` делит шпоровые цены на `economy.emerald_value_spurs` (по умолчанию 8), half-up, положительный результат не меньше 1. Таблица JSON `item_values` остаётся в шпорах; делится **сумма** оценки. Награда, минимум, NPC, потолки залога рангов и аванс стажёра идут через тот же делитель. Комиссия — доля уже введённой награды, второй раз не делится.
- Подпись валюты — `MoneyFormat`: Numismatics `item.numismatics.spur` / `item.numismatics.spur.plural` (RU «Шпора» / «шпор»), иначе `item.minecraft.emerald` / `ui.aerocouriers.currency.emerald.plural`.
- **30.10.2026, иконка.** Без загруженного Numismatics везде, где рисуется значок валюты, это `ItemStack` `minecraft:emerald` через `GuiGraphics.renderItem`, в том же размере (шапка 16 px, накладная и строка статистики профиля 8 px). Своей монетки нет. С Numismatics значок — как раньше (предметы монет; на накладной свой `waybill_spur`, если он есть). Текст сумм в деталях и модалке принятия иконки не рисует. Разбивка по номиналам (тултип) только при `numismaticsEconomy`; без неё суммы остаются текстом и на планшете, и на накладной.
- **30.10.2026, тултип.** `GuiGraphics.renderTooltip(font, List, Optional<TooltipComponent>, x, y)` с пустым списком строк и непустой картинкой роняет клиент: NeoForge 21.1.235 в `ClientHooks.gatherTooltipComponents` вставляет картинку по индексу 1. Разбивка шпор как раз так и вызывалась (`List.of()` + картинка, шапка и номиналы рисуются внутри `SpurBreakdownClientTooltip`). Все такие вызовы идут через `TooltipDraw`: картинка — `renderComponentTooltipFromElements` (пустой текст допустим, картинка единственный элемент; если текст есть, картинка стоит после первой строки, как у NeoForge). Пустой текст без картинки не рисуется. Пустая строка-заглушка не добавляется: она дублировала бы шапку «Баланс».
- **30.10.2026, профиль.** Строка «Ср. награда (успешн.)» рисует значок 8 px на одной базовой линии с подписью и суммой (`SpurAmountUi.drawLabeled`), по вертикали в пределах строки 8 px. Значок 16 px карточки стоял ниже подписи и закрывал «Среднюю дистанцию». Шапка по-прежнему 16 px в ряду вкладок высотой 20. «Средняя цена» заказчика остаётся текстом без значка.
- **30.10.2026, трекинг.** Слово валюты рисует только `MoneyText`: между буквами единицы 2 GUI-пикселя, остальной текст — обычный шаг шрифта. Жирный набор — побуквенно, вторая копия на +1 px не забивает этот зазор. Короткое обозначение только на второй строке карточки доски, если полное слово не оставляет зазор 8 px до залога и минимум под дистанцию: Numismatics `sp` / `шп`, изумруды `em` / `эм`. Залог на карточке остаётся полным словом и прижат вправо.

В модалке подтверждения «Отмена» / «Cancel» 78 px справа, остаток ряда — у кнопки принятия. ## Маршрут на картах Xaero (30.10.2026, по README макетов владельца)
- Линию рисуем **сами** через собственные элементы карты Xaero (dev-зависимость `compileOnly`), а не «Рисунками» (Drawings) Xaero и не миксинами. Публичного «мир → экран» у Xaero нет — калибруем по 4 невидимым элементам-пробам. Подробности и риски — [research/xaero.md](research/xaero.md).
- Маршрут — фиксированная ломаная (сейчас прямая от точки построения до цели). Коридор 32 блока (конфиг 16–96), задержка перестроения 2 с (0.5–10). Пройденная часть стирается.
- Перестроение: выход из коридора дольше задержки, смена отслеживаемого заказа или точки, погрузка (A→B), закрытие заказа, смена измерения.
- Цвета: к A — жёлтый, к B — голубой (как лучи `[navigation]`); до погрузки — тусклый пунктир A→B. Опция «контрастные цвета» — оранжевый/белый.
- Подпись на World Map: дистанция, ETA по реальной скорости (средняя за 10 с, иначе `fixed_speed`), время до срока; просрочка — красным. На миникарте подписи нет; цель за краем — наш значок с буквой A/B на рамке в сторону цели и шеврон внутри окна (30.10.2026, после проверки Grok: вейпоинт Xaero на краю виден не всегда — сторонние точки показываются только в наборе по умолчанию). Значок лежит ровно поверх точки Xaero, если та видна, двух значков нет.
- Классы Xaero разделены по модам (30.10.2026): типы миникарты (`xaero.common`/`xaero.hud`) и World Map (`xaero.map`) не встречаются в одном нашем классе. Каждая из комбинаций «нет Xaero / только миникарта / только World Map / оба» грузит только свои классы.
- Рисуется только **отслеживаемый** заказ (явно — «Показать на карте» в «Моих», иначе с ближайшим сроком). Остальные — по опции `other_orders`.
- Включено по умолчанию. Настройки — окно «Маршрут на карте» в своём профиле + `[route]` в `aerocouriers-client.toml`. Без Xaero ничего не рисуется, в окне строка статуса.
- Накладная: кнопка «Показать на карте» — World Map с пунктиром A→B; закрытие карты возвращает в накладную.
- Точки «через» не сделаны, в архитектуре оставлено место (`RoutePlan` принимает промежуточные точки).
- Мягкий отказ: если хук карты не встал или ведёт себя не так — линия на этой карте выключается до выхода из мира, вместо неё цепочка обычных временных точек Xaero (Minimap ≥ 26.2.0).
- Протокол сети: в `ZoneSync` добавлены срок и точка B. Ветка маршрута и 0.2.0 обе подняли протокол до `"2"` независимо и несовместимо, поэтому после слияния — `"3"`. Версия мода — 0.2.0-alpha из main.

## 0.2.0-alpha (30.10.2026): обучение, профили залога, уведомления
Спецификации: onboarding FLOW, collateral README, notifications FLOW (макетов не было). Где спецификация молчит или противоречит коду, решено так:

**Профили залога**
- Порядок сегментов: Мирный, Лёгкий, Нормальный, Сложный, Кастомный. По сети и в `economy.collateral_profile` идёт строковый ключ (`peace` / `easy` / `normal` / `hard` / `custom`), не номер enum.
- Мирный (`peace`): накладная показывает короткую табличку «Залога нет» (`ui.aerocouriers.create.no_collateral_plate`). Переключение на Мирный обнуляет залог незавершённых заказов (`OPEN`, `ACCEPTED`, `IN_TRANSIT`) и возвращает уже внесённый залог курьеру. История (`DELIVERED` / `FAILED` / `EXPIRED`) остаётся записью. *Решение владельца 30.10.2026 заменяет прежнее «ненулевой залог принятого заказа остаётся виден».*
- Кастомный (`custom`): поле залога свободное (0…200 % стоимости груза), при открытии накладной заполнено 50 %. Быстрые значения сделаны ссылками, а не кнопками.
- Название профиля видят только операторы. Игрок видит только эффект: поле залога есть или нет, сумма.

**Уведомления**
- Решение «показывать ли в чат» перенесено на клиент: сервер шлёт событие с категорией, клиент маршрутизирует. По умолчанию в чат идут только срочные. Action bar остаётся запасным путём для клиента без канала (старый клиент или мод не на клиенте).
- Пройденные пороги 5/2/1 мин не сохраняются: после рестарта сервера то же предупреждение может прийти ещё раз.
- «Контейнер далеко» срабатывает только после подбора груза (или когда контейнер уже в зоне B), с кулдауном на заказ. Пока контейнер не появился, «далеко» не бывает. Если контейнер в другом измерении, текст называет измерение (`far_container_dimension` / `far_container_behind_dimension`), а не дистанцию «0 блоков».
- Тосты рисуются своим рендером, а не через ванильный `ToastComponent`: нужен угол, очередь, «×N», показ поверх планшета и скрытие при F1/F3/чате/паузе. Пока тосты скрыты, они не теряются: потом приходит сводка «пропущено N».
- Срочный звук — тот же колокол, что у входящих, только ниже тоном, плюс note-block bell. Нового звукового ассета нет.
- Группы почты: текущая сессия без заголовка, затем «Пока вас не было» (с момента выхода до входа), затем «Раньше».
- Фильтр «Заказы» включает также обучение, админ-сообщения и доску. Отдельных фильтров у них нет: событий мало.
- Базовый цвет бейджа — синий (входящие), коралловый — когда среди непрочитанных есть срочное.
- `SimpleSoundInstance.forUI(sound, pitch, volume)`: раньше громкость и высота были перепутаны. Исправлено, громкость из `[notifications]`/`ui_volume` теперь работает.

**Задачи**
- «Завершено сегодня» — задачи, закрытые за последние 24000 тиков (игровые сутки), а не по календарю.
- Автоотслеживание отмечает «на экране» все заказы. Панель показывает 4 строки (срочные → закреплённые → по времени создания), остальное — «ещё N».

**Обучение**

## Накладная смотрит на публикатора (30.10.2026)
Макеты `mockups_2026-10-30d_waybill_facing`. Нормативно; сторона **статична**.

## Jade-тултипы контейнера и станции (0.3.0, 30.10.2026)

Сервер перепроверяет права. Ранг деревни от репутации не меняем; отдельный «уровень деревни» — бэклог.

## Разнообразие деревенских заказов (31.10.2026)
Решение владельца: M/L/XL, дорогие и редкие должны появляться в **обычной** генерации (`StationContractSource`), не только в `corkQa`. UI листков не меняем.
1. **Размер.** Тир репутации задаёт потолок: 0 → S, 1 → S+M, 2 → до L, 3 → до XL. Веса на верхнем тире по умолчанию S 45% / M 30% / L 17% / XL 8% (`[stations] village_size_weight_*`). Политика станции `allowsSize` отсекает запрещённые размеры.
2. **Манифест.** Сначала размер, потом груз, который **нуждается** в этом размере (`smallestFor`). Таблицы `village_cargo/*.json` обратно совместимы; новые поля опциональны. Не больше слотов/веса контейнера.
3. **Дорогие.** Порог остаётся 1000 (`EXPENSIVE_REWARD`) и репутация редких 25 не трогаем. ~10–15% заказов mid/top тиров выходят на порог за счёт веса, дистанции, `valuable`/`value_multiplier` и надбавки размера. Вклад обычного груза в награду ограничен `village_value_reward_cap` (иначе XL из пшеницы всегда «дорогой»). Ценная строка отправителя подмешивается отдельно (`village_valuable_inject_chance`), а не на каждый стак. Залог по-прежнему `npcCollateral` + `balanceNpcMoney` (залог ≥ награды).
4. **Редкие.** Тот же `tryInjectRare` (тир ≥ 1, шанс 0.35). Если замена ломает целевой размер — редкий стак откатывается.
5. **Микс.** Если за проход опубликован хотя бы один заказ, на доске остаётся минимум один S (когда политика это позволяет).
6. Версию мода и `PROTOCOL_VERSION` не поднимаем.
