# Aeronautics Couriers — уточнения к ГДД v3 (25.10.2026)

Источник истины — [`GDD.md`](GDD.md). Здесь собраны решения и замечания, принятые после его написания.

## Решения владельца (25.10.2026)
Ответы Egor на вопросы из `STATUS.md`. Нормативно; внесены в GDD v3.1.
1. **Лицензия мода — MIT** (`LICENSE`, `mod_license=MIT`). Из Create: Marketplace берём только идею UI и логику открытия окна (настраиваемое место кнопки). Их код не используем и не копируем.
2. **Сроки — игровые тики сервера.** Пока сервер выключен, таймер не идёт (GDD §5.4).
3. **Стартовый XP при миграции** 0 / 300 / 1500 / 5000 — оставить для теста.
4. **При провале** награда возвращается заказчику вместе с залогом курьера. Курьер рискует, но прозрачно: до принятия он видит, что именно потеряет (манифест, сообщение при принятии) (GDD §5.2, §7.2).
5. **Почтовая станция** `aerocouriers:post_station` — только для NPC-заказов, вместо колоколов (GDD §6).
   - Генерируется вместе с деревнями через worldgen, без ломания ванильных пулов и пулов других модов.
   - Есть UI с названием пункта: имя генерируется из словаря, оператор может его менять.
   - Администраторы ставят станции сами, чтобы создать свои пункты.
   - Атлас регистрирует станции, когда игрок с лицензией подходит ближе N блоков. Это и есть `ContractSource` для NPC-заказов.
6. **Контур зон частицами** — видит только курьер этого заказа, рисует клиент. Конфиг: плотность частиц и дальность (GDD §10.3).
7. **Крепление для верёвки** — `simulated:rope_connector` на контейнере, своей проушины нет. Проверено по исходникам Simulated 1.3.0 (GDD §9.4.1).
8. **Повреждение груза (пиратство)** — контейнер можно сломать или взорвать.
   - Заказ проваливается с причиной `DAMAGED`; залог и награда — заказчику.
   - Часть манифеста выпадает в мир один раз и атомарно.
   - Учитываются приваты и `[piracy]`; прочность и доля выпадения настраиваются.
   - Хрупкий груз (бэклог) пойдёт тем же путём (GDD §9.7).

## Погоны (рендер лицензии)
- Погоны — перенос из клиентского мода автора SkyPact Pilot Wings (`pilotwings`, исходники в `pilotwings_src.zip`, MIT, автор тот же).
- Сейчас он вешает `ICurioRenderer` на пять предметов KubeJS `kubejs:pilot_license_cadet/second/first/captain/admin`, ранг берётся из ID; две плоские пластины над плечами + glow-слой (`RenderType.eyes`).
- В новом моде: один предмет `aerocouriers:pilot_license`, ранг — Data Component `aerocouriers:license_rank` на предмете (сервер обновляет при повышении), рендер выбирает текстуру по компоненту. Текстуры: cadet → I, second → II, first → III, captain → IV, новая для V (Ас, пока заглушка), admin — отдельная (выдаёт оператор).
- Миграция: старая `kubejs:pilot_license_*` в слоте Curios при входе заменяется новой лицензией с владельцем и стартовым XP по рангу (таблица в конфиге).

## Особенности сборки MC-Ikaria (важно для дизайна)
1. **Мир — небесные острова, обычных деревень почти нет.** Решено (п. 5 выше): NPC-заказы идут только от почтовых станций. В обычных мирах станции генерируются в деревнях, на Ikaria их ставит администратор. Абстракция `ContractSource` остаётся.
2. **FFItemWeight** уже в сборке со своими весами предметов. Если мод установлен — брать вес груза из него (soft-dep), иначе свой `item_weights.json`.
3. **Дыра:** при провале деревенского/NPC-заказа груз НЕ отдаётся курьеру (иначе это покупка груза по оценке, выгодно при заниженной оценке редкого груза). Груз NPC-заказа при провале уничтожается.
4. В сборке есть мод Envelope со своими «курьерами» — избегать путаницы терминов в UI.
5. Waystones в сборке телепортируют только в пределах одного измерения — MVP «обе точки в одном измерении» согласуется.
6. ⚠️ Уточнить у Simulated Project, можно ли использовать слово «Aeronautics» в названии аддона.

## Xaero (временные точки) — проверено по байткоду Xaero's Minimap 26.6.0
- Подробно: [`research/xaero.md`](research/xaero.md).
- Основной путь: сторонние точки `xaero.hud.minimap.waypoint.thirdparty.ThirdPartyWaypoints` (Xaero ≥ 26.2.0), origin `aerocouriers:orders`, id `order-<uuid>`, `temp = true`, снимать `remove(id)` при завершении заказа, `clearOrigin` при выходе.
- Откат для Xaero < 26.2: `Waypoint(..., WaypointPurpose.DESTINATION, temp=true)`.
- `compileOnly` из `https://chocolateminecraft.com/maven` (`xaero.minimap:xaerominimap-neoforge-1.21.1:26.6.0`, `xaero.map:xaeroworldmap-neoforge-1.21.1:1.47.0`, `xaero.lib:xaerolib-neoforge-1.21.1:1.7.3`), jar Xaero НЕ класть в репозиторий (ARR). Мост грузится только при `ModList.isLoaded("xaerominimap")`, все вызовы в try/catch(Throwable), базовая навигация — луч + HUD.
- Выбор доставки на карте (штамп): колбэка нет — снимок вейпоинтов мира до открытия `GuiMap` (или `GuiWaypoints`) и сравнение после возврата; список существующих точек — запасной путь. Нет Y → высота игрока (иначе 64).

## Создание заказа штампом, доска только для мониторинга, одна станция на деревню (25.10.2026)
Решения владельца после теста доставки в игре. Нормативно; внесены в GDD.
1. **Штамп** `aerocouriers:courier_stamp` — единственный способ игроку создать P2P-заказ. ПКМ по контейнеру с инвентарём (сундук, бочка, двойной сундук, модовые через item handler) открывает окно: груз и точка погрузки берутся из этого блока, игрок указывает доставку (станция из атласа или координаты), награду/залог/срок/радиус. После подтверждения сундук на месте становится физическим грузовым контейнером (Sable), груз уходит в Escrow, исходный блок снимается без дропа.
2. **Команда** `/couriers contract create` остаётся для операторов и тестов (ленивое появление контейнера при подлёте, как раньше).
3. **Отмена / истечение штампового заказа:** груз возвращается **в почту заказчика**, физический контейнер снимается без дропа. Не восстанавливаем исходный сундук: тип контейнера (бочка, двойной, модовый) уже потерян, чанк может быть выгружен, на месте может стоять что-то другое. Почта уже есть в шапке доски.
4. **Стыковка с ленивым появлением:** у заказа флаг `preplaced`. Пока `OPEN`, контейнер уже стоит и не удаляется самопроверкой. При принятии заказ сразу `IN_TRANSIT` (контейнер уже есть; иначе слот ранга зависает, если курьер улетает до следующего тика). Командные заказы по-прежнему появляются при подлёте.
5. **Доска (J, кнопка инвентаря, `/couriers ui`, ПКМ по станции, ПКМ по планшету)** — только мониторинг: вкладки «Заказы» и «Мои», почта и баланс в шапке. Вкладки «Создать» нет. Вкладка «Тест» у оператора: плюс кнопка «Выдать штамп». Нужен **планшет заказов** в слоте Curios `order_tablet` или в руке; иначе подсказка «Нужен планшет заказов». Штамп по контейнеру планшет не требует. `[access] require_tablet = false` снимает проверку на сервере.
6. **Одна почтовая станция на деревню.** Причина дублей: элемент станции добавлен в пул домов, jigsaw может выбрать его несколько раз; прежняя проверка соседства шла в `onLoad` до регистрации соседа и ловила только уже стоящие рядом станции. Теперь регистрация деревенской станции откладывается на тик, дубль ищется в атласе и по старту структуры деревни в радиусе `stations.village_dedup_radius` (96). Лишняя заменяется столом картографа. Станции оператора не трогаем.

## NPC-заказы между станциями (итерация 5, 25.10.2026)
- Источник — **любые** станции в атласе: и деревенские, и поставленные администратором. На Ikaria деревень почти нет, поэтому админских станций достаточно. Пара в одном измерении, ≤ 10 000 блоков.
- Груз появляется физическим контейнером у станции погрузки сразу при публикации (`preplaced`). Награда минтится, со станции не списывается.
- При провале и истечении: залог сгорает, награда не выплачивается, груз уничтожается (не почта, не дроп).
- Стажировка: первые 3 принятых деревенских заказа без залога; после 3-й доставки — разовый аванс 100 сп.
- На доске NPC-заказ виден, если игрок открыл обе станции.
- Не в этой итерации: репутация станции, редкий груз, отдельное окно станции, лимит 800 блоков и подсказки стажёра.

## Отладка одиночной игры (25.10.2026)
- Серверный ключ `[debug] allow_self_accept = false` (только для тестов): если `true`, заказчик может принять свой P2P-заказ командой `/couriers contract accept` и кнопкой «Принять» на доске. В чат пишется предупреждение об отладочном режиме.
- Деньги и предметы идут на один UUID: игрок должен иметь на счёте награду + комиссию + залог. При доставке залог и награда возвращаются ему же (нетто − комиссия); при провале — то же. Почта, XP и `M_повтор` считаются как обычно (пара курьер+заказчик совпадает). Отдельной ветки выплат нет.
- Свой открытый заказ **не** занимает слот активных перевозок ранга. Лимит `maxActive` (rank1 = 1) считает только `ACCEPTED`/`IN_TRANSIT`, где этот игрок — курьер. `max_open_per_player` ограничивает только создание. Штамповый заказ при принятии сразу переходит в `IN_TRANSIT`. Отказ по лимиту называет id уже везущегося заказа.
