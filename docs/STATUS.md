- Команды `/couriers contract create|list|info|accept|abandon|cancel` (+ op: `forcespawn|forcedeliver|fail`), `/couriers mail [claim]`, `/couriers balance`, `/couriers money add|set` (см. README).
- Повторная команда не платит дважды: каждый переход сначала проверяет состояние.
- Тик раз в секунду: `OPEN` после `expiresAt` → `EXPIRED`; активный после окна опоздания → `FAILED` (истёк срок). Завершённые заказы чистятся через 30 дней.

### Итерация 3 — контейнер в цикле (GameTest'ы проходят, в клиенте не проверено)
- **Ленивое появление** (§9.1): раз в секунду, если курьер `ACCEPTED`-заказа ближе `spawn_trigger_radius` к точке погрузки, `ContractManager.spawnContainer` ищет ближайшую площадку 3×3×3 без жидкостей с прочной опорой (`cargo.spawn_search_radius`, по умолчанию 8; по высоте ±3), ставит контейнер с `fill` по весу, собирает в под-уровень Sable → `IN_TRANSIT`, звук и частицы, сообщение курьеру. Нет места → срок на паузе (`Timing.paused`), уведомление обоим раз в минуту. Команды `pickup`/`deliver` удалены.
- **Опечатка** (§9.2): GUI и capability инвентаря нет, `noLootTable`. Твёрдость −1 (механизмы Create не ломают), но игрок ломает за `piracy.break_seconds` независимо от инструмента; взрывоустойчивость — `piracy.blast_resistance`; `piracy.enabled = false` → неразрушим.
- **Самопроверка доставки** (§9.3): блок-сущность раз в 20 тиков → `checkContainer`: сфера зоны, скорость < `delivery_max_speed`, курьер в сети ближе 64 блоков, `delivery_still_checks` подряд. Неизвестный или завершённый заказ → блок удаляет себя.
- **Все виды провала** (§9.5, §9.7): `TIMED_OUT`, `ABANDONED`, `DESTROYED` (пустота; блок пропал без игрока и за 60 тиков никто с этим `contractId` не отчитался), `DAMAGED` (сломал игрок или взрыв; `BreakEvent`/`ExplosionEvent.Detonate` с приоритетом LOWEST — приваты могут отменить). Залог и награда всегда заказчику. `DAMAGED`: сначала `FAILED` и пустое хранилище, потом дроп `floor(count × drop_ratio)` в мировых координатах; сломал сам курьер — без дропа. Сообщения курьеру и заказчику с причиной.
- **Риск до принятия** (§7.2): строка «залог X сп и награда Y сп уходят заказчику» в `contract info` и в ответе на `accept`.
- **Частицы зон** (§10.3): S2C `aerocouriers:zone_sync` (при входе и при смене состояния заказа), клиент рисует три окружности сферы зоны: оранжевые — погрузка, зелёные — доставка. Клиентский конфиг `[zones]`: `enabled`, `particle_density`, `render_distance`. Пакет шлётся только клиентам с модом.
- **Dev-сервер (RCON):** `simulated:rope_connector`, поставленный в плот над контейнером, входит в тот же под-уровень (масса 34.0 → 34.25), у него есть BE держателя верёвки (`OwnStrand`) ✅.

### Фикс: лимит активных перевозок при самопринятии (25.10.2026)
- Ранг I = 1 активная перевозка. Считаются только `ACCEPTED`/`IN_TRANSIT` с этим UUID в поле `courier` (`ContractManager.activeJobs`). Свой `OPEN` (заказчик = курьер при `allow_self_accept`) слот не занимает; `DELIVERED`/`FAILED`/`EXPIRED` и отложенные провалы оффлайн-курьеров — тоже нет.
- `max_open_per_player` — только лимит **создания** (`unfinishedIssued`), не перевозок.
- Штамп после `accept` сразу `IN_TRANSIT` (контейнер уже стоит). Иначе при взлёте до следующего тика заказ зависал в `ACCEPTED`, самопроверка не доставляла, слот ранга не освобождался — в одиночке это выглядело как «нет активных заказов, а принять нельзя».
- Сообщение `too_many_active` называет id уже везущегося заказа. На доске самопринятый заказ в работе показывается как «везу я» (можно отказаться).
- GameTest'ы: `activeLimitIgnoresOwnOpenAndFreesAfterTerminal`, `stampSelfAcceptThenDeliverFreesTheSlot`.
- Jar: `aerocouriers-0.1.0-alpha-fix.jar` (PR #6, ветка `cursor/fix-active-order-limit-0ba6`).

### Итерация 5 — NPC-заказы между станциями (25.10.2026)

На Ikaria деревень почти нет — админские станции достаточно. Пара ≤ 10 000 блоков, не больше `village_board_max` открытых NPC, одна открытая пара в каждом направлении.
- Груз — datapack `data/aerocouriers/village_cargo/<biome>.json` (биом клетки станции; нет таблицы — `default`). Контейнер ставится сразу у станции погрузки (`preplaced`). Награда минтится в Escrow (со счёта станции не списывается).

### Вёрстка штампа и выбор точки на карте Xaero (после замечания владельца, 25.10.2026)
- Окно штампа: подписи **X/Y/Z** у координат и подписи награды/залога/минут/радиуса **над** полями (больше не наезжают на координаты). Раскладка `StampCreateLayout` считается от ширины/высоты окна и `font.lineHeight`; панель всегда влезает в экран. Пустое место уходит под сетку груза и перенос строки риска. Длинный текст — обрезка с тултипом или перенос. Проверено логикой на 1920×1080 / 1280×720 / 1366×768 / 1600×900 / 2560×1440 при GUI scale 2, 3, 4.
- Xaero — по-прежнему необязателен (`compileOnly` minimap 26.6.0 + worldmap 1.47.0 + xaerolib 1.7.3, jar не в репозитории). Без `xaerominimap` кнопки нет.
- С Xaero: кнопка «Выбрать на карте» открывает World Map (`GuiMap`, как клавиша M) или экран вейпоинтов миникарты. События создания точки нет — сравниваем список вейпоинтов текущего мира до открытия и после возврата; то же окно штампа восстанавливается с уже введёнными полями. Запасной путь — выпадающий список существующих точек. Нет Y у вейпоинта (`yIncluded=false` или Y=32767) → текущая высота игрока (иначе 64). Старые версии Xaero: `NoSuchMethodError`/`ClassNotFound` → кнопка скрыта.

## Известные проблемы и наблюдения
- **Туннелирование:** контейнеры, сброшенные с y=250 (≈63 бл/с к земле), пролетели сквозь тонкий пол плоского мира и падали дальше в пустоту. С y=100 — остановился. Провал «уничтожен» при падении в пустоту (`y < minBuildHeight`) сделан в итерации 3; контейнер появляется на земле у точки погрузки, а не с высоты.
- Сервер без игроков через 300 тиков перестаёт тикать block entity (ванильное поведение 1.21.1) — для тестов использовать `/forceload`. Физика Sable при этом продолжается.
- **Точность float на больших координатах:** при |x|,|z| ~ 1e7 (там GameTest ставит структуры) поза физики точна лишь до ~0.5–1 блока. На обычных координатах пака не мешает, но проверки доставки «по радиусу» нельзя делать с допуском меньше блока.
- Текстура погон ранга V — **заглушка** (копия ранга IV), нужна новая.
- `cargo_mass_scale` пока не влияет на массу: JSON `physics_block_properties` рассчитан для k = 0.25.
- `ModMenus` по-прежнему пустой: тестовая доска — `Screen` + пакеты, не контейнерное меню (27 слотов — в финальном UI).
- EMI/JEI не сдвигают кнопку инвентаря.
- **Sable 2.0.6:** если под-уровень опустел (контейнер удалён) в тот же тик, что и сохранение мира при остановке, Sable бросает «Body has been removed» в `SubLevelSerializer`. В GameTest'ах обходим ожиданием 40 тиков; на живом сервере нужен очень неудачный момент `/stop`, но это баг Sable — стоит сообщить авторам.
- Площадка для появления проверяется только по блокам мира: корабль (под-уровень Sable) над точкой погрузки её не занимает — контейнер может появиться внутри корабля ⚠️.
- **Приваты в полёте:** контейнер в плоте Sable, где приватов нет, поэтому моды приватов его не защищают; проверка по мировым координатам — через `compat/ClaimsBridge` (позже).
- `/couriers contract fail` и пропажа блока не роняют груз (`DESTROYED`); роняет только `DAMAGED`.
- Станций в деревне бывает 0 (вес элемента 4 из 68–87); можно поднять — лишние станут столами картографа. Старые дубли чинятся при загрузке BE, если станция ещё без `station_id`.
- Станции из зомби-деревень не добавляются (пулы `village/*/zombie/houses` не трогаем).
- Подсказка Jade/WTHIT при наведении на контейнер (§9.2) — не сделана.
- Итерация 2, сознательно не сделано: минимальный залог 50% оценки (нет оценки стоимости — `item_values.json` §8.3; NPC-залог пока `≈ 2×вес`), `pause_on_logout_singleplayer`, «удалённый заказчик — почта сгорает через 30 дней», индексы по курьеру/заказчику (пока перебор — заказов мало), сохранённые точки погрузки/приёма. Стажировка и аванс для деревенских заказов — сделаны в итерации 5.
- Деньги идут сразу на счёт, а не в почту (почта — только предметы).
- Версия Numismatics в паке — 1.1.0 (в GDD — 1.0.20); API моста не сверен.
