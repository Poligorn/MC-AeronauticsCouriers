## Сделано

### Инфраструктура
- Gradle 9.2.1 + ModDevGradle 2.0.148, Java 21, компиляция против NeoForge **21.1.235** (минимум). `./gradlew build` проходит.
- Зависимости: Curios 9.5.1 (`implementation`), Sable 2.0.6 (`compileOnly`), Sable Companion 1.6.0 (`jarJar`). Версии сверены с паком MC-Ikaria.
- Документация: GDD, CLARIFICATIONS, исследование Xaero, проверка API (`docs/research/api-verification.md`), правила `.cursor/rules/*.mdc`.

### Итерация 0 — перенос с KubeJS (код готов, частично проверен)
- Предмет `aerocouriers:pilot_license` (`ICurioItem`), слот Curios `license` (datapack + тег `curios:license`). На dev-сервере Curios загрузил 11 слотов (10 стандартных + `license`) и 1 файл сущностей ✅.
- Data Components `aerocouriers:license_owner` (UUID, ник, номер) и `aerocouriers:license_rank` (`rank1..rank5`, `admin`).
- Data Attachment `aerocouriers:courier_profile` (`CourierProfile`, `copyOnDeath`).
- Привязка владельца при первом надевании и синхронизация ранга с профилем раз в секунду (`Licenses.tickWorn`); `admin` не перезаписывается.
- Номера лицензий — `LicenseRegistry` (SavedData).
- Рендер погон перенесён из pilotwings, текстура по компоненту ранга; иконка предмета тоже по рангу (item property `aerocouriers:rank`).
- Миграция `kubejs:pilot_license_*` при входе (слоты Curios + инвентарь), стартовый XP по таблице `[migration]` в серверном конфиге.
- Команды: `/couriers profile`, `/couriers license give|migrate`, `/couriers xp add|set`.
- Серверный и клиентский конфиги со всеми ключами GDD §15 (+ `[migration]`, `cargo.debug_log_interval_ticks`).

### Итерация 1 — прототип Sable (проверено на dev-сервере без игроков, через RCON)
- Блок `aerocouriers:cargo_container_s` со свойством `fill=0..8`, неразрушаемый, без предмета и инвентаря; BE хранит только `contractId` (+ флаг `debug`).
- `/couriers spawncargo [pos] [fill]` ставит блок, пишет `contractId` в BE **до** сборки и собирает его в под-уровень (`SableBridge.assembleSingleBlock`).
- Результаты прогона (Sable 2.0.6, Create 6.0.10, Aeronautics 1.3.0):
  - ✅ сборка одного блока работает, `afterMove` вызывается (блок уезжает в плот `~20 481 032, 128, ~20 481 032`);
  - ✅ BE в плоте читает свой `contractId`, мировые координаты и скорость через Companion разумны (падение 11 → 63 бл/с, на земле 0);
  - ✅ масса по `fill`: 0 → 2.0, 4 → 34.0, 8 → 66.0 (`/sable info`);
  - ✅ смена `fill` у уже собранного объекта пересчитывает массу (34 → 66), BE сохраняется;
  - ✅ рестарт сервера: под-уровень, BE и масса восстанавливаются, `onLoad` срабатывает.
- `/couriers cargo list` — последние известные координаты/скорости (`CargoTracker`, в памяти).

### Итерация 2 — контракты и хранилище (без GUI, через команды)
- Модель: `Contract` (record + Codec), `ContractState` (переходы GDD §5.2 проверяются, недопустимый — исключение), `ContractType`, `Destination` (измерение + позиция + радиус).
- SavedData на overworld: `ContractManager` (заказы, отложенные провалы оффлайн-курьеров, журнал доставок для `M_повтор`), `Escrow` (манифест, награда, залог по заказу), `Mailbox` (предметы по игрокам), `InternalEconomy` (балансы).
- Правила: `RankRules.requiredRank` и лимиты рангов §4.2 (залог, контейнер, дистанция, активные заказы), `Pricing` (мин. награда `D/100`, комиссия, ×0.5 при опоздании), `Weights` (значения по умолчанию §8.2, запрет шалкеров/бандлов), `XpCalculator` (§4.1).
- Деньги — только через `Economy`; обёртка пишет каждое движение в `<мир>/aerocouriers/transactions.log` (время, операция, игрок, сумма, причина `reward:<id>`/`collateral:<id>`…, баланс после).
- Команды `/couriers contract create|list|info|accept|pickup|deliver|abandon|cancel|fail`, `/couriers mail [claim]`, `/couriers balance`, `/couriers money add|set` (см. README).
- Повторная команда не платит дважды: каждый переход сначала проверяет состояние.
- Тик раз в секунду: `OPEN` после `expiresAt` → `EXPIRED`; активный после окна опоздания → `FAILED` (истёк срок). Завершённые заказы чистятся через 30 дней.

## Известные проблемы и наблюдения
- **Туннелирование:** контейнеры, сброшенные с y=250 (≈63 бл/с к земле), пролетели сквозь тонкий пол плоского мира и падали дальше в пустоту. С y=100 — остановился. Для итерации 3: провал «уничтожен» при падении в пустоту (`y < minBuildHeight`), рассмотреть ограничение скорости/высоты появления.
- Сервер без игроков через 300 тиков перестаёт тикать block entity (ванильное поведение 1.21.1) — для тестов использовать `/forceload`. Физика Sable при этом продолжается.
- **Точность float на больших координатах:** при |x|,|z| ~ 1e7 (там GameTest ставит структуры) поза физики точна лишь до ~0.5–1 блока. На обычных координатах пака не мешает, но проверки доставки «по радиусу» нельзя делать с допуском меньше блока.
- Текстура погон ранга V — **заглушка** (копия ранга IV), нужна новая.
- `cargo_mass_scale` пока не влияет на массу: JSON `physics_block_properties` рассчитан для k = 0.25.
- `ModMenus`/`ModPayloads` пустые до итерации 4.
- Итерация 2, сознательно не сделано: минимальный залог 50% оценки (нет оценки стоимости — `item_values.json` §8.3), стажировка и аванс (только для деревенских заказов), `pause_on_logout_singleplayer`, «удалённый заказчик — почта сгорает через 30 дней», индексы по курьеру/заказчику (пока перебор — заказов мало), сохранённые точки погрузки/приёма.
- Деньги идут сразу на счёт, а не в почту (почта — только предметы).
- Версия Numismatics в паке — 1.1.0 (в GDD — 1.0.20); API моста не сверен.
