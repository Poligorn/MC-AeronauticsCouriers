## 1. Видение

**Одной фразой.** Вы — пилот с лицензией. Берёте контракт, вносите залог, сами решаете, на чём и как везти *физический* контейнер через полмира. Довезли — деньги и ранг. Разбились — залог у заказчика.

### Столпы
1. **Груз — физический объект.** Тяжёлый контейнер требует мощного аппарата; его можно уронить, потерять, разбить.
2. **Доверие через залог.** Как в EVE: заказчику не нужно знать курьера — его страхует залог.
3. **Минимум блоков.** Доска — одно окно мониторинга. Предмет для создания заказа — штамп. Новых блоков два: контейнер (появляется сам или из сундука со штампом) и почтовая станция (ровно одна на деревню, или её ставит администратор, §6).
4. **Работает и в одиночке.** NPC-заказы почтовых станций — полноценный цикл без других игроков.
5. **Ранг — это доступ.** Больше доставок → тяжелее, дальше, дороже.

### Целевая аудитория
- Игроки Create Aeronautics, которым нужна *цель* для полётов.
- Серверы с экономикой Numismatics.
- Одиночные игроки, исследующие мир на дирижаблях.

## 2. Основной цикл

```
           ┌────────────── Окно мода (клавиша J / кнопка в инвентаре) ──────────────┐
           │                                                                       │
 ЗАКАЗЧИК  │  Штамп по сундуку → груз + награда в хранилище → доска (мониторинг) │
           │                                                                       │
 КУРЬЕР    │  Доска → смотрит манифест → ПРИНЯТЬ (залог списан)                    │
           └───────────────────────────────────────────────────────────────────────┘
                 │
                 ▼
   Штамп: контейнер уже стоит в точке погрузки.
   Команда/тест: курьер подлетает ближе 64 блоков → контейнер появляется.
                 │
                 ▼
   Курьер цепляет/грузит → летит → садится в зоне доставки
                 │
       ┌─────────┴──────────┐
       ▼                    ▼
   ДОСТАВЛЕН             ПРОВАЛ (таймаут / уничтожен / повреждён / отказ)
   курьер: награда       курьер: теряет залог (это видно до принятия)
     + залог + XP        заказчик: залог курьера + своя награда обратно
   получатель: груз      груз: курьеру, в почту заказчика, выпадает
     в почтовом ящике      в мир (повреждён) или потерян — см. §9.5
```

**Длительность одного цикла:** 5–15 минут (стажёр) → 15–30 минут (капитан).

## 3. Лицензия пилота

### 3.1 Предмет
- ID: `aerocouriers:pilot_license` (замена пяти предметов `kubejs:pilot_license_*`).
- Слот Curios `license`, размер 1.
- На игроке рисуется **погонами**: рендер переносится из клиентского мода SkyPact Pilot Wings (`pilotwings`, `ru.skypact.pilotwings.EpauletteRenderer`) ✅.
- **Погоны = ранг**: своя текстура на каждый ранг, видно издалека, хороший социальный сигнал.

#### 3.1.1 Как устроен рендер сейчас (pilotwings 1.0.0) ✅
- Отдельный мод только для клиента (`dist = Dist.CLIENT`), зависит от Curios.
- В `FMLClientSetupEvent` вешает `ICurioRenderer` на пять предметов KubeJS: `kubejs:pilot_license_cadet / second / first / captain / admin`.
- Ранг берётся из ID предмета: `pilot_license_cadet` → `cadet`.
- Две плоские пластины 4×4 px (3 px на тонких руках) над плечами, привязаны к `rightArm` / `leftArm` модели игрока, видны сверху и снизу.
- Два прохода: базовая текстура `epaulette_<ранг>.png` (`entityCutoutNoCull`) и светящийся слой `epaulette_<ранг>_glow.png` (`RenderType.eyes`, полная яркость), приподнятый на 0.001 против мерцания.
- Текстуры 16×16, лежат в `assets/pilotwings/textures/entity/`.

#### 3.1.2 Что меняется в Aeronautics Couriers
- Рендер входит в мод (клиентский класс `client/EpauletteRenderer`), отдельный `pilotwings` и пять предметов KubeJS убираются.
- Предмет один, поэтому ранг берётся не из ID, а из Data Component `aerocouriers:license_rank` на лицензии. Сервер обновляет его при повышении. Так погоны видны **другим** игрокам без отдельной синхронизации профиля: Curios сам передаёт надетый предмет клиентам.
- Текстуры: `epaulette_rank1..rank5` + `epaulette_admin` (+ `_glow`). Пять старых текстур переиспользуются: cadet → I, second → II, first → III, captain → IV; для V Ас нужна новая; admin остаётся отдельной (выдаёт оператор).
- Миграция: при входе старая `kubejs:pilot_license_*` в слоте меняется на новую лицензию с владельцем и стартовым XP, соответствующим рангу (таблица в конфиге).

### 3.2 Где хранятся данные
| Данные | Где | Почему |
|---|---|---|
| Владелец (UUID, ник), номер лицензии | Data Component на предмете | Предмет «именной», виден в подсказке |
| XP, ранг, статистика, история | Data Attachment игрока `CourierProfile` (`copyOnDeath = true`) | Потеря или кража предмета ≠ потеря прогресса |

### 3.3 Правила
- **Выдача:** в окне мода кнопкой «Получить лицензию» (бесплатно один раз). Крафта нет.
- **Привязка:** при первом надевании пустой лицензии на неё записывается владелец.
- **Чужая лицензия** не даёт доступа к вкладке «Курьер» (подсказка: «Принадлежит: Poligorn»).
- **Переоформление** взамен утерянной: платно (×2 за каждую следующую) — небольшой расход денег из экономики.
- **Подсказка к предмету:** владелец, ранг, доставлено / провалено, процент успеха, пройденное расстояние.

## 4. Ранги и прогрессия

### 4.1 Опыт
```
XP = (10 + D/200 + W/50) × M_срок × M_повтор
D — расстояние по прямой между точками, блоки
W — вес груза, ед. (см. §8.2)
M_срок   = 1.0 вовремя · 0.5 с опозданием до +25% срока (дальше — провал)
M_повтор = 1.0 → 0.1 за повторные P2P-заказы от одного заказчика за сутки (анти-альт)
Провал: XP не отнимается, но учитывается в проценте успеха
```

### 4.2 Таблица рангов

| Ранг | XP | Шевроны | Макс. залог | Макс. контейнер | Макс. дистанция | Активных заказов |
|---|---|---|---|---|---|---|
| I Стажёр | 0 | 1 | 200 сп | S | 1 500 | 1 |
| II Курьер | 300 | 2 | 600 сп | M | 4 000 | 2 |
| III Пилот | 1 500 | 3 | 2 000 сп | L | 10 000 | 2 |
| IV Капитан | 5 000 | 4 | 6 000 сп | L ×2 | ∞ | 3 |
| V Ас | 15 000 + успех ≥ 90% | 5 | ∞ | L ×4 | ∞ | 3 |

«Активных заказов» — только перевозки этого курьера в `ACCEPTED`/`IN_TRANSIT`. Свои открытые заказы (как заказчик) слот не занимают; при самопринятии один и тот же UUID не считает свой `OPEN` активной доставкой.

### 4.3 Расчётная кривая (модель, проверена расчётом)

| Переход | XP за типичный заказ | Минут на заказ | Заказов | Часов игры |
|---|---|---|---|---|
| I → II | 16.5 | 6.8 | 19 | ~2 |
| II → III | 27 | 9 | 45 | ~7 |
| III → IV | 48 | 11.4 | 73 | ~14 |
| IV → V | 81 | 13.6 | 124 | ~28 |
| **Итого до V** | | | **261** | **~51** |

Допущения: скорость аппарата 8 → 25 блоков/с по мере роста, погрузка 5–8 минут, обратный путь пустым на 60%. **Калибровать после плейтеста** — всё вынесено в конфиг.

### 4.4 Почему опыт, а не счётчик доставок
Счётчик поощряет спам коротких заказов. Опыт зависит от дистанции и веса — растёт тот, кто берёт серьёзную работу.

## 5. Контракты: общая модель

### 5.1 Поля
| Поле | Описание |
|---|---|
| `id` | UUID |
| `type` | `VILLAGE` / `PLAYER` |
| `issuer` | UUID игрока или ID деревни |
| `recipient` | UUID игрока (по умолчанию = заказчик) или ID деревни |
| `courier` | UUID или null |
| `origin`, `destination` | измерение + координаты + радиус зоны |
| `manifest` | список ItemStack (лежит в хранилище, **не** в блоке) |
| `weight`, `value` | рассчитываются автоматически |
| `reward`, `collateral` | спуры |
| `requiredRank` | рассчитывается, заказчик может только повысить |
| `deadline` | длительность на выполнение после принятия, в **игровых тиках сервера** (§5.4) |
| `expiresAt` | когда снять с доски, если никто не взял |
| `state` | см. 5.2 |

### 5.2 Состояния
```
OPEN ──принят──▶ ACCEPTED ──контейнер появился──▶ IN_TRANSIT ──в зоне, стоит──▶ DELIVERED
  │                 │                                  │
  │истёк/отмена     │отказ/таймаут                     │таймаут/уничтожен/отказ
  ▼                 ▼                                  ▼
EXPIRED           FAILED ◀─────────────────────────────┘
(груз и награда   (залог курьера и награда → заказчику;
 → почтовый ящик   груз — по таблице §9.5)
 заказчика)
```
- Отменить можно только в `OPEN`.
- После `ACCEPTED` заказчик **не может** отменить: курьер уже внёс залог.
- **Решение владельца:** при любом провале награда возвращается заказчику **вместе с залогом курьера**. Курьер рискует, но прозрачно (§7.2).

### 5.3 Требуемый ранг
```
requiredRank = max(ранг_по_залогу, ранг_по_контейнеру, ранг_по_дистанции)
```
Недоступные заказы видны на доске **серыми с замком** — это мотивирует расти.

### 5.4 Время (решение владельца)
- Все сроки (`deadline`, `expiresAt`, окно опоздания) считаются в **игровых тиках сервера** (время работы сервера, `overworld.getGameTime()`), а не в реальном времени.
- Пока сервер выключен, таймеры не идут. В одиночной игре — пока мир не запущен.
- ❌ Было: «реального времени» в §7.1.

## 6. NPC-заказы: почтовые станции (одиночная игра и сервер)

> **Решение владельца:** NPC-заказы привязаны не к колоколам, а к **почтовой станции** — блоку `aerocouriers:post_station`. Станция — единственный источник автогенерируемых заказов (реализация `ContractSource`). Для P2P-заказов станция не нужна. ❌ Было: атлас по колоколам.

### 6.0 Почтовая станция
- Блок `aerocouriers:post_station` с блок-сущностью: название пункта и его id.
- **Генерация с деревнями:** станция добавляется в структуры деревень через worldgen. Ванильные пулы и пулы других модов при этом не ломаются: мы только **добавляем** свой элемент в пул улиц/домов при запуске сервера и никого не заменяем. ✅ Реализовано (`village/VillageStructures`): при `ServerAboutToStartEvent` элемент `aerocouriers:village/post_station` (3×3×3, jigsaw `minecraft:building_entrance`) с весом 4 дописывается в пулы `minecraft:village/{plains,desert,savanna,snowy,taiga}/houses`. **Одна станция на деревню:** jigsaw может выбрать элемент станции несколько раз в одном пуле домов. При первой загрузке регистрация откладывается на тик; дубль (тот же старт структуры деревни или станция ближе `stations.village_dedup_radius`, по умолчанию 96) становится столом картографа. Станции оператора не заменяются. На Ikaria (острова без деревень) станции ставит администратор.
- **Ставит администратор:** оператор ставит станцию сам (креатив или `/give`), чтобы сделать свой пункт доставки. У игроков в выживании предмета нет.
- **Название:** генерируется из datapack-словаря (`data/aerocouriers/station_names/*.json`), когда станция появляется. Оператор может переименовать её в окне станции (ПКМ, итерация 4) или командой `/couriers station rename <pos> <имя>` ✅. Словарь по умолчанию — 40 русских названий; закончились — к имени добавляется номер.
- **Окно станции (UI):** в итерации 5 ПКМ открывает общую доску-мониторинг. Отдельное окно (название пункта, заказы отсюда) — отложено. Переименовывать может только оператор (`/couriers station rename`).

### 6.1 Атлас станций
- Станция регистрируется в атласе, когда игрок **с лицензией** подходит к ней ближе `stations.register_radius` (32) блоков → «Почтовая станция «Ясная Поляна» добавлена в атлас».
- Без поиска по всему миру (`/locate`): дёшево для сервера и награждает исследование.
- На сервере атлас общий; на доске видны заказы между станциями, которые открыл сам игрок.

### 6.2 Генерация
- Каждые `village_generation_interval_min` (10) минут — пары **любых** станций в атласе одного измерения (деревенские и поставленные администратором) в пределах 10 000 блоков. На Ikaria деревень почти нет, поэтому админских станций достаточно. Не больше `village_board_max` (12) открытых NPC; одна открытая пара в каждом направлении. Ручной прогон: `/couriers station generate`.
- На доске NPC-заказ виден игроку, если он открыл **обе** станции (оператор видит все).
- Груз — по таблицам биома клетки станции: отправитель → `produces`, получатель → `consumes`; пересечение, иначе всё, что производит отправитель.
  `data/aerocouriers/village_cargo/<biome>.json` (нет таблицы — `default.json`).
- Груз **генерируется** сразу: физический контейнер (`preplaced`) ставится у станции погрузки. У игрока ничего не забирается. Награда минтится в Escrow.

### 6.3 Деньги
- Награда: `16 + (D/60) × (1 + W/400) + W × reward_per_weight` спуров ×0.8–1.2 (`[contracts.pricing] reward_per_weight`, по умолчанию 0.04).
- Залог: когда появится `item_values.json` (§8.3) — оценка груза; пока `≈ 2×вес`.
- При провале залог **сгорает**, награда не выплачивается, груз уничтожается — главный расход денег в экономике.
- Без Numismatics: внутренний баланс; обмен изумрудов (1 изумруд = 8 сп) — позже.

### 6.4 Репутация станции
- +1 за доставку на станцию или с неё, −3 за провал.
- Пороги и бонусы настраиваются в `[stations] reputation_tier_thresholds` и `reputation_tier_bonus_percent` (по умолчанию 10/25/50 → +10/+20/+30% к награде NPC при доставке; берётся больший уровень отправителя и получателя).
- **Редкий груз:** при генерации NPC-заказа, если репутация станции-отправителя ≥ первого порога, с шансом `village_rare_roll_chance` (по умолчанию 0.35) один стак манифеста заменяется записью из datapack `data/aerocouriers/village_cargo/rare/*.json` (`min_reputation`, `weight`, предмет или `enchanted_book`). Залог — через `item_values.json` и `Pricing.npcCollateral`. На доске — иконка и подсказка «Редкий груз».
- ✅ Итерация 5: репутация, множитель, редкий груз, окно станции (уровень и следующий порог в строке репутации).

### 6.5 Стажировка
- Первые **3 заказа** (`trainee_free_contracts`) — без залога. ✅
- После 3-го — аванс `trainee_bonus` (100 сп), чтобы было чем платить залог. ✅
- Пока остаются бесплатные деревенские заказы: принять можно только NPC-маршруты ≤ `trainee_max_distance` (800 блоков по умолчанию, 0 = без лимита). ✅ Генератор предпочитает короткие пары. Подсказка на вкладке «Заказы» доски. ✅

## 7. Игровые контракты (P2P)

### 7.1 Создание
**Игрок** создаёт заказ только **транспортной накладной** `aerocouriers:transport_waybill` (ПКМ по контейнеру с инвентарём; одна накладная списывается при успешной публикации). Команда `/couriers contract create` — для операторов и тестов.
1. Заказчик кладёт груз в контейнер (до 27 стаков) и оформляет накладную. Предметы **сразу** уходят в хранилище сервера; исходный блок снимается без дропа и на том же месте становится физическим грузовым контейнером (`preplaced`).
2. Точка погрузки = позиция этого контейнера. Точка доставки: станция из атласа или координаты вручную.
3. Ставит награду и залог.
   - Минимальный залог = 50% оценки (конфиг). Если залог меньше оценки — красное предупреждение: «Курьер сможет выгодно не довезти груз».
   - Минимальная награда = `ceil(D / reward_distance_divisor + W × reward_per_weight)` сп (по умолчанию `D/100 + 0.04×W`, против спама).
4. Срок: 30 минут – 7 дней **игрового времени сервера** (§5.4; пока сервер выключен, срок не идёт).
5. **Комиссия** `round(награда × p2p_fee × fee_multiplier[размер])` (сгорает) + награда удерживается сразу. Лимит ранга на **размер контейнера при создании** не действует — заказчик платит больший множитель за M/L/XL (`[contracts.pricing] fee_multiplier_s/m/l/xl`, по умолчанию 1.0 / 1.5 / 2.5 / 4.0 при `p2p_fee = 0.05`). Ограничение размера остаётся для **курьера** при принятии.

### 7.2 Принятие
- Курьер видит **полный манифест** до принятия — защита от мошенничества с подсунутым мусором.
- **Прозрачность риска (решение владельца):** в манифесте и в сообщении при принятии явно написано, что курьер теряет при провале: «При провале (срок, отказ, уничтожение или повреждение груза) вы потеряете залог N сп; награду M сп получит обратно заказчик». В сообщении о принятии повторяется сумма залога.
- Свой заказ принять нельзя (исключение для одиночных тестов: `[debug] allow_self_accept`, по умолчанию `false`).
- Лимит ранга считает только уже принятые перевозки этого курьера. Свой открытый заказ при самопринятии слот не занимает; отказ называет id уже везущегося заказа. Штамповый заказ при принятии сразу `IN_TRANSIT`.
- Залог списывается атомарно; не хватает денег — кнопка неактивна.

### 7.3 Точка погрузки
- Штамп ставит контейнер на место исходного блока. Командный заказ ищет свободную площадку 3×3×3 с твёрдым основанием.
- Если точка в привате (FTB Chunks / Open Parties and Claims) — заказчик автоматически даёт «права на погрузку» в радиусе 8 блоков (если API привата доступен ⚠️). Иначе предупреждение при создании заказа.

Порядок источников: (1) datapack `item_values.json` → (2) средняя цена из Create: Marketplace, если он установлен ⚠️ → (3) значение по умолчанию по редкости.

### 8.4 Масса в физике ✅
- Блок контейнера имеет свойство `fill = 0..8`.
- Datapack Sable `physics_block_properties/cargo_container_s.json`:
```json
{
  "selector": "aerocouriers:cargo_container_s",
  "properties": { "sable:mass": 2.0 },
  "overrides": {
    "fill=1": { "sable:mass": 10.0 },
    "fill=2": { "sable:mass": 18.0 },
    "fill=8": { "sable:mass": 66.0 }
  }
}
```
- `fill` = доля веса от максимума × 8. Масса: `2 + fill × W_max × k / 8`, где `k = cargo_mass_scale` (по умолчанию 0.25).
- L: масса распределена по 8 блокам в `physics_block_properties/cargo_container_l.json` (суммарно ~514 при `fill=8`, `k=0.25`).
- ⚠️ Прототип: устойчив ли Rapier при суммарной массе S/M/L ~66/194/514. Если нет — снижаем `k` в конфиге и datapack.

## 9. Грузовой контейнер и Sable

### 9.1 Появление (ленивое)
1. Заказ `ACCEPTED`, точка погрузки показана на карте.
2. Курьер подходит ближе 64 блоков → чанк гарантированно загружен.
3. Сервер ставит блок контейнера на площадку и превращает его в отдельный физический объект ✅:
```java
BlockPos anchor = pickupPos;
level.setBlock(anchor, ModBlocks.CARGO_S.get().defaultBlockState()
        .setValue(CargoContainerBlock.FILL, fill), Block.UPDATE_ALL);
// BE получает contractId ДО сборки — данные переедут вместе с блоком
((CargoContainerBE) level.getBlockEntity(anchor)).bind(contract.id());

BoundingBox3i bounds = new BoundingBox3i(anchor.getX() - 1, anchor.getY() - 1, anchor.getZ() - 1,
                                         anchor.getX() + 2, anchor.getY() + 2, anchor.getZ() + 2);
ServerSubLevel sub = SubLevelAssemblyHelper.assembleBlocks(level, anchor, List.of(anchor), bounds);
```
4. Состояние → `IN_TRANSIT`, частицы и звук «прибытия груза».

> Штамповые заказы — исключение: контейнер ставится сразу, потому что чанк точно загружен и груз уже лежит в мире. Командные/тестовые заказы по-прежнему ленивые: заказчик может быть оффлайн, иначе мир засоряется ненужными объектами. При отмене или истечении штампового заказа контейнер снимается, груз уходит в почту заказчика (исходный сундук не восстанавливаем).

### 9.2 Опечатка
- GUI контейнера не открывается; воронки, лотки, трубы Create и Mechanical Arm **не видят** инвентарь (capability не предоставляется).
- **Контейнер можно повредить** (решение владельца, §9.7): у него есть прочность (`piracy.break_seconds`), его можно сломать или взорвать. Тогда заказ проваливается с причиной `DAMAGED`. Если пиратство на сервере выключено (`piracy.enabled = false`), контейнер неразрушим, как раньше. ❌ Было: «сломать нельзя никому».
- Сломанный контейнер ничего не роняет сам. Груз выпадает только из хранилища (§9.7).
- Внутри блока лежит **только `contractId`**. Предметы лежат в хранилище сервера → дюп невозможен по построению.
- Подсказка при наведении (Jade/WTHIT, если установлены): номер заказа, получатель, срок.

### 9.3 Самопроверка доставки ✅
> ❌ Поправка (25.10.2026): перегрузки `projectOutOfSubLevel(Level, Vec3)` и `getVelocity(Level, Vec3)` в Sable Companion 1.6.0 помечены `@Deprecated(ScheduledForRemoval "2.0.0")`. Использовать JOML-версии `projectOutOfSubLevel(Level, Vector3dc, Vector3d)` / `getVelocity(Level, Vector3dc, Vector3d)` (см. `cargo/SableBridge`, `docs/research/api-verification.md`). Скорость — в блоках/с.

Блок-сущность контейнера раз в 20 тиков (реализовано в итерации 3: `CargoContainerBlockEntity.serverTick` → `ContractManager.checkContainer`):
```java
Vector3d world = SableBridge.worldCenter(level, worldPosition);   // projectOutOfSubLevel, JOML
Vector3d vel   = SableBridge.velocity(level, worldPosition);      // getVelocity, блоков/с
Verdict v = ContractManager.get(server).checkContainer(level, contractId, world, vel.length());
// внутри: зона доставки (сфера радиуса зоны) && |v| < delivery_max_speed
//         && курьер заказа в сети, в том же измерении и ближе 64 блоков (защита от «угона», §12)
//         && delivery_still_checks проверок подряд → доставка; y < minBuildHeight → DESTROYED
if (v == Verdict.REMOVE) level.removeBlock(worldPosition, false);  // заказ завершён или неизвестен
```
- Маркер, как в Delivery Required, **не нужен**: контейнер сам знает свой заказ.
- Работает одинаково, где бы ни был контейнер: отдельный объект, привязан верёвкой или встроен в корабль (§9.4).
- Защита: если `contractId` неизвестен менеджеру (сломанный/устаревший) → блок удаляет себя.

### 9.4 Как курьер везёт контейнер
Все способы разрешены — это и есть геймплей:
| Способ | Механика | Проверка |
|---|---|---|
| Буксир на верёвке | Верёвки и лебёдка Aeronautics. Крепление — `simulated:rope_connector`, которое игрок ставит на контейнер (§9.4.1) | ✅ по исходникам: к чему цепляется верёвка; ✅ dev-сервер: коннектор в плоте рядом с контейнером входит в тот же под-уровень; ⚠️ клиент: установка рукой и сама верёвка |
| Захват Sticker'ом | Как в готовых схемах «грузовых вертолётов» на CreateMod.com | ⚠️ |
| Встраивание в корабль | Корабль пересобирают вместе с контейнером → блок переезжает в «плот» корабля | ⚠️ `BlockSubLevelAssemblyListener.afterMove` ✅ — переносим привязку |
| Поезд Create, грузовик Offroad | Любой транспорт Sable | ⚠️ |

#### 9.4.1 Крепление для верёвки ✅ (исходники Simulated 1.3.0)
- `RopeItem.isValidRopeAttachment` цепляет верёвку только к блок-сущности Create (`SmartBlockEntity`) с поведением `RopeStrandHolderBehavior`. Такое поведение есть у `simulated:rope_connector` и `simulated:rope_winch`. К обычному блоку, в том числе к нашему контейнеру, верёвка **не цепляется**.
- `RopeConnectorBlock` — направленный блок без проверки опоры: его можно поставить на любую грань.
- **Решение:** своей проушины не делаем. Игрок ставит обычный `simulated:rope_connector` на грань контейнера. Блок, поставленный на грань физического объекта, Sable помещает в его плот, значит коннектор становится частью **того же под-уровня**. ✅ Проверено на dev-сервере 25.10.2026: `setblock simulated:rope_connector` в плоте над контейнером — масса под-уровня 34.0 → 34.25, у коннектора есть блок-сущность держателя верёвки (`OwnStrand`). ⚠️ Установка рукой игрока и натяжение верёвки — нужен клиент. Свой блок с `RopeStrandHolderBehavior` потребовал бы зависеть от внутренних классов Create и Simulated.
- Коннектор — имущество игрока: при доставке или провале контейнер исчезает, а коннектор остаётся (его можно снять).
- Ломать коннектор — не повреждение груза.

### 9.5 Провал
Во всех случаях **награда возвращается заказчику** вместе с залогом курьера (NPC: залог сгорает, награда не выплачивается).

| Причина | Залог | Груз | Контейнер |
|---|---|---|---|
| Истёк срок | → заказчику (NPC: сгорает) | P2P: в почту курьера, если контейнер появился; NPC: уничтожается | Исчезает |
| Курьер нажал «Отказаться» | → заказчику | P2P: в почту курьера, если контейнер появился | Исчезает |
| Контейнер уничтожен (пустота, `/sable` удалил объект, блок пропал без игрока) | → заказчику | **Потерян** | — |
| Контейнер **повреждён** (`DAMAGED`: сломан игроком или взрывом, §9.7) | → заказчику | Доля `piracy.drop_ratio` **выпадает в мир** (лут для пиратов), остальное уничтожается. Сломал сам курьер → всё уничтожается | Разрушен |
| Контейнер ни разу не появлялся (не подлетел) | → заказчику | Возвращается заказчику в почтовый ящик | — |

> MVP-упрощение ⚠️: вместо «распечатывается для курьера на 10 минут» груз P2P-заказа сразу уходит в почту курьера, а контейнер исчезает.

> Логика EVE: заказчик сам определяет размер залога. Если залог меньше стоимости груза, курьеру выгоднее «не довезти». Окно предупреждает об этом при создании заказа.

### 9.6 Опоздание
- 0–100% срока — норма.
- 100–125% — «опоздание»: награда ×0.5, XP ×0.5, залог возвращается.
- \>125% — провал.

### 9.7 Повреждение груза (пиратство) — решение владельца
- Контейнер может сломать **любой** игрок, не только курьер (если позволяют сервер и приват). Время ломания не зависит от инструмента: `piracy.break_seconds` (по умолчанию 10 с). Устойчивость к взрывам — `piracy.blast_resistance`.
- Сломан или взорван любой блок контейнера (у L — любая часть) → заказ сразу проваливается с причиной **`DAMAGED`**:
  - залог курьера и награда → заказчику (как в §5.2);
  - манифест **один раз и атомарно** переносится из хранилища в мир: заказ сначала переходит в `FAILED`, хранилище опустошается, и только потом предметы появляются дропом в мировых координатах контейнера. Повторный вызов ничего не находит — дюпа нет;
  - выпадает доля `piracy.drop_ratio` (по умолчанию 0.5) каждого стака (округление вниз), остальное уничтожается;
  - сломал сам курьер → ничего не выпадает (иначе это покупка груза за залог, см. CLARIFICATIONS «Дыра»);
  - сообщения: курьеру — «Груз заказа … повреждён: <кто>, залог потерян», заказчику — «Груз повреждён, залог курьера и награда возвращены».
- **Приваты:** ломание — обычное событие ломания блока NeoForge, его отменяют моды приватов. ⚠️ Контейнер в полёте стоит в плоте Sable, где приватов нет; проверка привата по мировым координатам — через `compat/ClaimsBridge` (позже).
- **Сервер без пиратства:** `piracy.enabled = false` → контейнер неразрушим и не взрывается.
- Хрупкий груз (провал при ударе > X, бэклог §17) использует этот же путь с причиной `DAMAGED`.

### 10.3 Навигация
- **Без зависимостей:** луч-маяк в точке погрузки и доставки (только для курьера) + компас в HUD с расстоянием.
- **Контур зоны частицами:** курьер **этого** заказа видит зону погрузки (пока `ACCEPTED`) и зону доставки (пока `IN_TRANSIT`) как частицы по границе сферы, которую проверяет сервер: горизонтальная окружность на уровне точки и две вертикальные (реализовано, ⚠️ вид не проверен в клиенте). Рисует только клиент; сервер присылает курьеру его активные зоны. Клиентский конфиг `[zones]`: `enabled`, `particle_density` (частиц на блок контура), `render_distance` (блоков).
- **Окно накладной (0.1.9–0.1.11):** планшет-клипборд (прессованный картон, стальной зажим, лист бумаги; без латунной рамки). Блоки **1 ГРУЗ / 2 УСЛОВИЯ / 3 МАРШРУТ / 4 ИТОГ**. На листе груз — одна строка из 9 ячеек; если слотов больше 9, ссылка «показаны 9 из M · все ячейки» открывает оверлей полной сетки (M 2×9, L 3×9, XL 5×9), Esc закрывает только оверлей. У S строка «Занято N из 9» без ссылки. Скрытые стаки — метка «+N» на девятой ячейке. Оверлей всегда поверх строки ячеек. Ошибки под полем; неактивная «Опубликовать» с причиной слева. Шрифт `aerocouriers:paper` — кириллица без тофу; ⚠ и стрелки — `PixelGlyphs`. Пикер точки B: вкладки Станции / Карта Xaero / Точка (XYZ). После успеха — штамп «ОПУБЛИКОВАНО», затем доска. Раскладка `WaybillCreateLayout` от 640×360. Если экран меньше макета, та же раскладка целиком уменьшается pose-scale, а мышь переводится в координаты листа (0.1.11). Заказчик может только **повысить** требуемый ранг (`minRankLevel`, сервер `max(auto, floor)`).
- **С Xaero's Minimap (≥ 26.2.0):** временные точки погрузки и доставки ✅.
  - Используем **сторонние точки** Xaero (`xaero.hud.minimap.waypoint.thirdparty.ThirdPartyWaypoints`): хранятся только в памяти, не пишутся на диск, группируются по нашему `ResourceLocation`. На этом же механизме Xaero показывает точки Waystones.
  - Origin `aerocouriers:orders`, id точки `order-<uuid заказа>` (уникальный: если игрок удалил точку, Xaero запоминает удаление по id), цвет GOLD, `temp = true`.
  - Видны на миникарте, в мире и на World Map 1.47.0 — **но только при выбранном наборе точек «по умолчанию» или «все наборы»**. Пишем об этом в подсказке.
  - Снимаем `remove(id)` при доставке/провале/отказе, `clearOrigin(origin)` при выходе из мира.
  - Xaero 25.x–26.1 (нет сторонних точек): обычная `Waypoint(..., WaypointPurpose.DESTINATION, temp=true)` в текущем наборе — не сохраняется на диск и сама удаляется, когда игрок подлетел ближе 4 блоков.
  - **Чем лучше Marketplace:** у них точка постоянная (`temp=false`), пишется в файл и не удаляется никогда; работает через рефлексию по устаревшему API `xaero.common.*`.
  - Доступ (проверено на 26.6.0):
    ```java
    MinimapSession s = BuiltInHudModules.MINIMAP.getCurrentSession();
    MinimapWorldRootContainer root = s.getWorldManager().getAutoRootContainer();
    MinimapWorldContainer c = root.addSubContainer(root.getPath().resolve(
        s.getDimensionHelper().getDimensionDirectoryName(dim)));
    c.getThirdPartyWaypointManager().get(ORIGIN)
     .add("order-" + id, new Waypoint(x, y, z, name, "✉",
          WaypointColor.GOLD, WaypointPurpose.NORMAL, true));
    ```
  - Мост `client/XaeroBridge` грузится только при `ModList.get().isLoaded("xaerominimap")`, все вызовы в `try/catch (Throwable)`: API у Xaero не публичный и уже переименовывался (`WaypointWorld` → `MinimapWorld`, `WaypointsManager` → `MinimapSession`). При любой ошибке — откат на луч + HUD.
  - ⚠️ Не проверено: mod ID fair-play версии (`xaerominimapfair`?).
- **Выбор точки доставки на карте (окно штампа):** отдельного события «вейпоинт создан» в Xaero 26.6.0 / World Map 1.47.0 нет ✅.
  - Кнопка только если `xaerominimap` загружен и сессия миникарты жива; без Xaero кнопки нет.
  - Открытие: `new GuiMap(null, null, WorldMapSession.getCurrentSession().getMapProcessor(), camera)` — тот же путь, что клавиша M. Нет World Map — `GuiWaypoints` миникарты.
  - После закрытия любого экрана `xaero.*` сравниваем список вейпоинтов текущего мира (все наборы, без third-party и death) с снимком до открытия; новый (`identityHashCode` + свежий `createdAt`) → поля X/Y/Z. То же окно штампа восстанавливается с уже введёнными значениями.
  - Запасной путь: выпадающий список существующих вейпоинтов игрока.
  - Нет Y (`isYIncluded() == false` или Y = 32767) → текущая высота игрока (иначе 64); в форме пометка, Y можно править.
  - Код Xaero только в `XaeroMinimapAccess` / `XaeroWorldMapAccess`; фасад `XaeroMapPicker` без типов Xaero. `NoSuchMethodError` / `ClassNotFound` → кнопка скрыта. `compileOnly` (+ `xaerolib` 1.7.3). ⚠️ в игре с паком не проверено.

## 12. Крайние случаи

| Ситуация | Решение |
|---|---|
| Курьер вышел из игры с грузом | Таймер идёт (как в EVE). Конфиг `pause_on_logout` для одиночки — по умолчанию ВКЛ в одиночной игре, ВЫКЛ на сервере |
| Сервер выключен | Таймеры стоят: сроки — в игровых тиках сервера (§5.4) |
| Контейнер сломали или взорвали | Провал `DAMAGED`, часть груза выпадает в мир (§9.7) |
| Контейнер в чужом привате | Ломание отменяет мод привата; в плоте Sable приватов нет ⚠️ (`ClaimsBridge`) |
| Рестарт сервера в полёте | Физический объект сохраняется Sable; блок-сущность при загрузке перерегистрируется в менеджере по `contractId` ⚠️ проверить в прототипе |
| Чанк с контейнером выгрузился (курьер улетел без него) | Таймер идёт; на карте метка «последнее известное место» |
| Получатель оффлайн | Груз в почтовом ящике, ждёт сколько угодно |
| Заказчик удалён/забанен | Залог при провале → в почту заказчика; через 30 дней сгорает |
| Точка погрузки занята блоками | Ищем свободную площадку в радиусе 8; нет — уведомление заказчику, срок на паузе |
| Точка в чужом привате | Предупреждение при создании; см. §7.3 |
| Другое измерение | MVP: обе точки в одном измерении. Позже — межпространственные заказы (бонус) |
| Контейнер утонул | Контейнер плавает, если масса позволяет (`sable:volume`); утонул и не достать до конца срока → провал |
| Контейнер «украли» (другой игрок увёз) | Доставить может только курьер заказа: при доставке проверяется, что курьер в радиусе 64 блоков. Украденный контейнер — провал курьера (как в EVE) |
| Операторская команда `/sable` удалила объект | Блок исчез и не появился в другом месте за 3 с → провал «уничтожен» |
| Контейнер упал в пустоту | Мировая `y` ниже дна мира → провал «уничтожен» |

## 13. Защита от злоупотреблений

| Угроза | Защита |
|---|---|
| Дюп груза | Предметы только в хранилище сервера; блок — пустая оболочка с ID |
| Дюп при повреждении | Переход в `FAILED` и опустошение хранилища — до дропа; повтор ничего не находит (§9.7) |
| Курьер ломает свой контейнер ради груза | Ничего не выпадает, залог теряется |
| Подмена груза | Манифест виден до принятия; заказчик не может менять заказ после публикации |
| Фарм XP альтами | `M_повтор`, минимальная награда, комиссия 5% (фарм стоит денег), XP только от награды ≥ `D/100` |
| Спам заказами | ≤ 10 открытых заказов на игрока, минимальная награда, комиссия |
| Подделка пакетов | Клиент шлёт только намерения (`accept(id)`); сервер проверяет всё: ранг, деньги, лицензию, расстояние |
| Взлом доставки «телепортом» контейнера | Скорость ≈ 0 три проверки подряд + курьер рядом; лог перемещений для админов |
| Самоограбление (заказчик сбивает курьера или ломает контейнер) | Разрешено: курьер теряет залог, заказчик получает залог и награду, груз частично выпадает (§9.7). Курьер видит риск до принятия. Конфиг `[piracy]` на сервере (ранее `pvp_rules`) |

### 14.2 Ключевые решения
- **Источник истины — сервер.** Клиент получает только снимок доски (пагинация по 20 заказов) и свой профиль.
- **Деньги — только через `Economy`.** Все операции идемпотентны и логируются (`transactions.log`).
- **Опциональные моды** (Numismatics, Xaero, Jade, приваты) подключаются через `ModList.isLoaded()` и изолированные классы-мосты — без них мод работает.
- **Sable — обязательная зависимость** (мод без физики теряет смысл). Companion встраивается Jar-in-Jar ✅.

public static boolean isLicensedCourier(Player p) {
    return findLicense(p)

        .filter(o -> o.uuid().equals(p.getUUID()))

## 18. Риски и открытые вопросы

| Риск | Вероятность | Что делаем |
|---|---|---|
